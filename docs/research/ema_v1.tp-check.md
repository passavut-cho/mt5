# ตรวจ TP ≠ 2×SL (T-012) — SmartEA_ema_v1.htm

**ข้อสรุป: ไม่ใช่บั๊ก — เป็นผลของการปัดราคาลง tick grid ไม่ต้องแก้โค้ด**

## วิธีตรวจ
อ่านตาราง Orders (SL/TP) จับคู่กับตาราง Deals (ราคา fill ของ deal `in`) ผ่านเลข order แล้วคำนวณ
`|TP−fill| − 2×|fill−SL|` ครบทั้ง 440 ไม้ (XAUUSD tick = 0.01)

## ผล
- ไม้ที่ต่างเกิน 0.02 ตามเกณฑ์ T-008: 24/440
- **ทั้ง 24 ไม้ต่างกัน 0.02 พอดี** (ไม่มีไม้ใดเกิน) — ที่ถูกนับเพราะ floating point (0.0200000001 > 0.02) • ไม่มีไม้ที่ต่าง > 0.02 เลย
- สัดส่วนต่อ TP distance ≈ 0.02/(3–22) = 0.1–0.5%

## สาเหตุ
`OpenWithRetry` (SmartEA.mq5:271–274) คำนวณ SL/TP จาก entry = ask/bid แล้ว `CTradeManager::Open` ปัดแต่ละตัวแยกกัน:
- SL ปัด **เข้าหา entry** (`NormalizeSlPrice`, T-010) → คลาดได้ 0 ถึง <1 tick
- TP ปัดใกล้สุด (`NormPrice`) → คลาด ±0.5 tick
- ผลต่าง TP − 2×SL = e_tp − 2·e_sl → ได้สูงสุด ~2.5 tick; ในข้อมูลจริงเจอสูงสุด 2 tick

fill = ราคา ask/bid ที่ใช้คำนวณ (Model=1, ไม่มี slippage) จึง **ไม่ใช่** สมมุติฐาน fill ต่างจากราคาอ้างอิง
และ T-010 ไม่ได้ทำให้ผิดทิศ (SL ถูกปัดเข้าหา entry → risk จริง≤ ที่คำนวณ)

## ข้อเสนอ (ไม่ทำ)
ปัด TP ให้ = 2×(ระยะ SL ที่ปัดแล้ว) จะได้ R:R เป๊ะ แต่ผลต่ำกว่า 0.5% ของ TP และต้องแตะ
`CTradeManager::Open` (ชั้น Trade) — ไม่คุ้ม ปล่อยไว้ ถือว่าเกณฑ์ spec ข้อ 9 ข้อ TP=2R ผ่านโดยมี tolerance 2 tick
